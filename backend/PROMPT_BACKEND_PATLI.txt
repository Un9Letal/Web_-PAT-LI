# 🤖 PROMPT: Backend Node.js — Sistema Web con Chatbot Generativo para Gestión de Ventas (PAT-LI)

## CONTEXTO DEL PROYECTO

Eres un desarrollador backend senior. Debes construir el backend de un **MVP** para un sistema web con chatbot generativo basado en IA, orientado a optimizar la **atención al cliente y gestión de ventas** de la empresa comercial PAT-LI (venta minorista textil, Ica - Perú).

El sistema debe:
- Integrar un chatbot generativo usando la API de OpenAI (GPT-4o o similar)
- Gestionar ventas, clientes, productos e inventario
- Registrar conversaciones del chatbot y evaluar satisfacción
- Dar soporte multicanal (web, WhatsApp futuro)
- Ser medible: tiempo de respuesta, eficiencia de ventas, satisfacción del cliente

### PASO 4 — Middlewares

**`auth.middleware.js`**: Extrae Bearer token del header, verifica con `jwt.verify()`. Si es inválido retorna 401. Adjunta `req.user = payload`.

**`role.middleware.js`**: Factory `requireRole(...roles)` que verifica `req.user.rol` contra los roles permitidos. Retorna 403 si no autorizado.

**`validate.middleware.js`**: Recibe un schema Joi, valida `req.body`. Si hay error retorna 422 con detalles de validación.

**`error.middleware.js`**: Captura todos los errores, loguea con winston, responde `{ success: false, message }` con código apropiado.

### PASO 5 — Módulo CHATBOT (el más importante)

**`chatbot.service.js`** — Lógica completa:

```javascript
// Flujo del servicio:
// 1. Recibir { mensaje, id_cliente, id_conversacion? }
// 2. Si no hay id_conversacion → crear nueva en chatbot_conversaciones
// 3. Guardar mensaje del cliente en chatbot_mensajes (emisor: 'cliente')
// 4. Recuperar historial de la conversación (últimos 10 mensajes)
// 5. Construir array de messages para OpenAI:
//    - system: SYSTEM_PROMPT con contexto de productos disponibles
//    - messages: historial mapeado
//    - user: mensaje actual
// 6. Llamar openai.chat.completions.create()
// 7. Medir tiempo de respuesta
// 8. Guardar respuesta en chatbot_mensajes (emisor: 'bot')
// 9. Actualizar tiempo_respuesta_promedio en la conversación
// 10. Retornar { respuesta, id_conversacion, tiempo_respuesta_ms }
```

**Contexto dinámico**: Antes de llamar a OpenAI, el servicio debe consultar los primeros 10 productos activos de la BD e inyectarlos en el system prompt como contexto:

## REGLAS DE GENERACIÓN

1. **Nunca** uses `res.json()` directo en controllers — siempre usa `responseHelper`
2. **Siempre** valida inputs de escritura (POST/PUT) con schemas Joi
3. El módulo **chatbot** es el más crítico: mide tiempo de respuesta con `Date.now()`
4. **Ventas**: Al crear venta, el service debe descontar stock de cada producto en una transacción Sequelize (`t = await sequelize.transaction()`)
5. **Soft delete**: Clientes y Productos usan `estado = 0`, no `DELETE` físico
6. Las rutas del chatbot `/api/chatbot/mensaje` deben funcionar **sin autenticación** (para que el widget del frontend funcione libremente)
7. Logs: usa winston para errores internos, morgan para HTTP access log
8. Incluye comentarios JSDoc en los services

## MÉTRICAS PARA LA TESIS (RF11 / RNF07)

El sistema debe capturar automáticamente:

| Indicador | Dónde se guarda | Cómo medirlo |
|-----------|-----------------|--------------|
| Tiempo de respuesta chatbot | `chatbot_conversaciones.tiempo_respuesta_promedio` | `Date.now()` antes/después de OpenAI |
| Eficiencia de ventas | `evaluacion_sistema.eficiencia_ventas` | ventas cerradas / consultas totales × 100 |
| Satisfacción del cliente | `satisfaccion_cliente.calificacion` | promedio de calificaciones 1-5 |
| Consultas atendidas | `consultas.estado` | count por estado |

El endpoint `GET /api/dashboard/chatbot-metricas` debe retornar estos 4 KPIs listos para graficar en el frontend.
